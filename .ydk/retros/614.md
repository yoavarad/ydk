Epic 614 ("Replace API-key LLM calls with subagent handoff") removed the hard dependency on `ANTHROPIC_API_KEY`. Before it, every ydk LLM call went through the Anthropic SDK, so `ydk memory retrospective` exited 1 without a key, never wrote `.ydk/retros/<epic>.md`, and the retro gate then blocked `ydk task start`. The epic added a handoff provider: the CLI writes a request file `.ydk/llm/requests/<id>.json` (id = sha256 of purpose, system, user and schema), prints a `YDK-SUBAGENT-REQUESTS` block and exits 3; the calling agent has subagents write schema-valid JSON to `responses/<id>.json`; rerunning the same command consumes the responses. `ai.provider` is `subagent` for new repos (`ydk init` writes it), `anthropic` remains available, and `claude-cli` is an optional headless provider. The dead strands-agents dependency was removed. Stories: #616 (core: 623, 624, 628), #617 (callers: 625, 626), #618 (docs and skill: 627). Merged 2026-11-01 05:38 UTC to 2026-11-02 04:46 UTC; 625 and 626 merged within seconds of each other at ~21:27 UTC on 11-01.

### Patterns
- The design held up across callers: `SubagentHandoff` derives from `BaseException` so fail-open `except Exception` callers cannot swallow it; request ids are content hashes so reruns are idempotent; collect mode batches fan-out callers (all reviewer requests in 625, all open-task requests in 624) into one handoff.
- 625 and 626 were developed in parallel and touched the same prompt-construction area. 626 merged with the Anthropic route's spec `cache_control` dropped, noted in its follow-ups as pending `cacheable_context` from 625; 625 then restored `cache_control` on the spec block for the reviewer engine. Prompt caching for spec text in the verification plugins (626) was not restored.
- Review leftovers were documented rather than fixed in every task (ADR 0004 for 623; follow-up lists in 624, 625, 626, 627). The ones with the most behavioural risk are in the follow-ups below.
- PR #661 (task 633) wired ContradictionDetector into `memory extract` only, not `index_all`; it is outside the six tasks listed for this epic but used the same provider route.
- PR bodies for 628 and 633 are only "Task N" plus a truncated verification block; 623, 624, 625, 626, 627 have real summaries.

### Template suggestions
- PR bodies should always carry Summary text and a Test Plan, as 623's does (behaviour summary, leftovers, console block with counts).
- Task comments listing "Known follow-ups" should become tasks, not stay as comments (see Follow-ups).

### Rule suggestions
- Run full pytest suites serially across parallel orchestrators; three suites in parallel exhausted memory.
- Before starting a batch, make sure the local main checkout is current: a stale checkout lacked the epic-638 retro and the retro gate blocked task start.
- When two parallel tasks touch the same prompt path, name in the task which one owns the shared field (here `cacheable_context`) so neither drops behaviour.
- Retro PRs are opened by hand because `ydk task done` refuses `.ydk`-only diffs.

### Summary
Epic 614 made ydk usable without an Anthropic API key: extract, retrospective, analyze-complexity, spec verify and the AI verification plugins all route through a provider that can hand work to subagents, and the retro gate can be satisfied that way. Main carried-forward risks: the unfixed review follow-ups below, and lost prompt caching for spec text in the AI plugins (626).
