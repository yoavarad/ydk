- Systematic migration from AWS Bedrock to Anthropic API across all LLM integration points

### Template suggestions
- LLM Provider Migration Checklist: 1) Establish canonical protocol/interface, 2) Implement new provider, 3) Update config defaults, 4) Migrate dependent components, 5) Remove old provider, 6) Comprehensive verification sweep
- Configuration Update Template: Identify all config classes affected by vendor change → Update defaults → Delete obsolete vendor configs → Document new required dependencies
- API Integration Template: Define target API contract (Messages API, tool_choice, cache_control) → Implement in new provider class → Route existing call sites through new provider → Remove legacy implementation paths

### Rule suggestions
- All vendor-specific implementations must route through a canonical provider protocol before being called by downstream code
- Configuration classes must be updated atomically when switching external dependencies; no partial AWS/Anthropic mixed states
- Every major library replacement must conclude with a comprehensive reference audit to ensure no legacy code paths remain
- New LLM providers must be implemented with explicit support for required features (tool_choice, cache_control, etc.) before migration of dependent components
- Embedding functions should prioritize local/self-hosted solutions over external API calls to reduce operational dependencies
- Migration tasks should follow a strict order: protocol definition → implementation → integration → cleanup → verification
