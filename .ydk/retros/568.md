## AI Analysis
No AI analysis available. `ydk memory retrospective --epic 568` listed the 10 tasks, then failed with "Claude API: invalid or missing API key". The sections below were written by hand from the issue and PR bodies.

### Patterns
- Review of a merged fix spawned a follow-up task in four cases. 571 created labels with `gh label create --force`, which overwrites existing colour/description, and its test locked `--force` in; 590 replaced that with a single `gh label list` and creation of only the missing labels. 572 ignored the `--remove-label` return code silently; 588 added a comment and a warning log, a fake `gh` that actually removes labels, and a CLI-level `task close` test. 589 extended label cleanup to the GitLab close path. 592 removed the stale "ignition required" claim from `skills/ydk/SKILL.md` once 570 landed.
- Test doubles were too lenient. The `FakeGh` in `tests/core/test_migrate.py` ignored `--remove-label`, so 572's behaviour was not really exercised until 588. 588 tested through the CLI against a stateful gh fake, mocking only the gh boundary.
- 573 followed TDD with a Hebrew/accented component and schema under a forced ASCII default encoding (red before the fix, green after), instead of relying on a Windows-only environment.
- 574 added the `python-cli-basic` stack so non-REST CLIs no longer get `cli-error-handling` and `cli-output-format`. This resolved the stack item in #567 without touching `python-cli`.
- 591 was filed from `ty` warnings seen during 570/572, but on main `ty` 0.0.34 reported 0 diagnostics and every `ty: ignore` was still needed, so it was closed as not reproducible.

### Template suggestions
- PR bodies for 570, 571, 572 are only "Task N" plus truncated verification blocks, with no Summary text or Test Plan counts. 573, 599, 601, 602, 603 show the better shape: a Summary of behaviour, a console block with test/ruff results, `Closes #N`.
- A follow-up task filed from a review should name the originating PR and task (588 and 590 did: "Follow-up from review of #587/#585") and quote the acceptance line that was missed.

### Rule suggestions
- A test double for an external CLI (`gh`, `glab`) must model the state change the code under test depends on (labels removed, issues closed); otherwise assert at the CLI level.
- Idempotent setup commands must not use overwrite flags such as `gh label create --force`; list existing state and create only what is missing.
- Best-effort calls whose return code is ignored need a comment saying why, and should log a warning on failure.
- Every `read_text()`/`open()` of repository files must pass `encoding="utf-8"`.

### Summary
Epic 568 let projects that skip ignition or use non-REST CLIs run the task lifecycle: `task start` accepts a missing `todos.yaml`, `init --remote github` creates the labels ydk needs (without overwriting existing ones), `task close` clears `in-review`/`in-progress` on GitHub and GitLab, `component validate` reads UTF-8 on Windows, and a `python-cli-basic` stack exists. Main carried-forward risk: label handling on GitLab is only partly covered (see follow-ups), and `guard.py` formatting from #567 has no task in this epic (no task or PR found mentioning it).
