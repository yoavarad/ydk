### Patterns
- The fix was split by layer. 550 added the reporting path: a skipped status in the verification model, `proof_capture.save_report` writing `SKIPPED`, `pr_template` rendering `SKIP`, and the dotnet-build/format/test plugins returning `detail: {status: SKIPPED, skip_reason}`. 552 then applied that convention to every other bundled plugin with a self-skip path (go-*, helm-lint, lint-ruff, tests-pytest, types-ty, tdd-guard, terraform-*), leaving output text unchanged.
- 552 added `tests/verifications/test_self_skip_convention.py`, a guard test parametrized per plugin: any plugin whose source has skip text must declare the SKIPPED status. This makes the convention enforceable for future plugins.
- 551 was a pure deletion (plugin, manifest, its 174-line test, stack default, catalog entries) with a one-line ADR update, so it was safe to run in parallel with 550.
- Tooling dogfooded itself: the PR bodies for 550/551/552 carry the verification blocks produced by the pre-fix and post-fix pipelines.

### Template suggestions
- Task 550's PR body is only "Task 550". A verify-behaviour PR should state the new status contract in its Summary, as 552 did.
- PR bodies for 550 and 551 lack a Test Plan section with test counts; 552's too. Counts only appear inside truncated proof blocks.

### Rule suggestions
- A new bundled verification plugin that can self-skip must return `detail.status == "SKIPPED"`; the guard test in 552 enforces it.
- A verification result must never count a skip toward `passed`.

### Summary
Epic 548 made verification reports honest about skipped checks: self-skips from every bundled plugin now surface as SKIP in proofs, PR bodies and summary counts, and the redundant `dotnet-quality` plugin is gone. Main risk carried forward: ai-code-review and spec-alignment still use the legacy `skipped` flag, and projects that vendor older plugin copies in `.ydk/verifications/` do not get the fix.
