## AI Analysis
No AI analysis available. `ydk memory retrospective --epic 385` failed with "Claude API: invalid or missing API key", so the sections below were written by hand from the 30 merged PR bodies (PRs 412-425, 434, 438-452) and the orchestrator run logs.

### Patterns
- Go was never on PATH on the dev host. Every go build/vet/smoke test is gated and was skipped locally (394, 406, 435, 436, 437), so CI was the only real Go verification for the whole epic.
- make/kind/docker/kubectl were also missing on the Windows host, so the Makefile and local-environment targets (408, 409) were never executed end to end.
- Fix tasks clustered on three origins: 8 of 30 tasks (426-433) were follow-ups to 404 (x4), 401 (x2) and 406 (x2). All 8 were known review leftovers or bugs found by compiling generated output, not regressions found in production.
- The pack was first built around the driving project (clopy-paste): samples, ext technology list (`("kafka",)`), description-regex binding, id-substring crosscut selection. Three late tasks (435, 436, 437) were needed to make it generic.
- Heuristic detection was repeatedly accepted as a known limit (per-line skip detection, table-driven case detection, `t.Run` name normalisation) and later partly fixed.
- Windows-specific breakage recurred: CRLF in ignited shell files (408), cp1252 crash (406), shell timeout orphaning grandchildren (393).

### Template suggestions
- feat(catalog): <phase> for <pack> -- with an explicit "verified locally / CI-only" line in the Test Plan
- fix(<area>): <leftover> from #<origin task> -- link origin task in the body (as 426-433 did)

### Rule suggestions
- A stack's toolchain (go, helm, make, kind) must be on PATH for the machine running its tasks, or the task's PR body must state "CI-only verification" and CI must run the gated tests.
- Packs driven by one consumer project must ship a neutral minimal sample from the first task, not as a late cleanup task.
- Bind and select by explicit fields (`ext_ref`, `kind`, `tags`), never by regex on descriptions or id substrings.
- Changes to shared core (`src/ydk/core/**`) from a pack task must be called out in the PR body (436 changed `core/ignition.py` for all Go packs).

### Summary
Epic 385 added Go + Kubernetes stack support across 30 tasks: verification plugins (generic command, go-quality, helm-lint), guard/TDD configurability, per-language TODOs and test traceability, the go-http-service ignition pack (app, container/Helm/OpenShift, Makefile + kind/Strimzi), CI generation for GitHub and GitLab, stack-aware doctor, and stack-neutral docs. The epic closed with three generalisation tasks that removed clopy-paste-specific assumptions from the pack. Main risk carried forward: most Go/Kubernetes behaviour was verified only in CI, never on a dev host.
