- Editing via PowerShell Get-Content/Set-Content corrupted a UTF-8 em dash on Windows.

### Rule suggestions
- Review by a separate agent is mandatory, even when the orchestrator thinks the task is small; 685 shows what it catches.
- LLM-backed steps that run inside an indexing or batch loop must catch provider errors so the primary operation still completes.
- Escape user or LLM text before printing through Rich markup.
- Mock only at system boundaries; do not stub internal functions such as `find_knowledge_contradictions`.
- On Windows, edit files with byte-safe utf-8 tools (Edit/Write), not PowerShell Get-Content/Set-Content.
- Flaky tests should be root-caused; a flake can be a swallowed transient error in production code (686).
